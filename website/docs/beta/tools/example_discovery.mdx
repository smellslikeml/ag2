# Discovering Verified Tool Examples

Tool descriptions are what the LLM reads to decide *when* and *how* to call a tool, so grounding them in real usage examples improves invocation accuracy. AG2 can generate these examples for you — either from the tool's schema, or by actually *playing* with the tool and keeping only the invocations that succeed.

This capability is an adaptation of [PLAY2PROMPT: Zero-shot Tool Instruction Optimization for LLM Agents via Tool Play](https://arxiv.org/abs/2503.14432v2){.external-link target="_blank"}: propose candidate invocations, execute them against the real tool, observe the result or error, reflect on failures, and keep the invocations that actually worked as verified usage examples — with no labelled data.

## Schema-derived examples with `add_examples`

The simplest option is to pass `add_examples=True` to the [`@tool`](/docs/beta/tools/tools) decorator. This appends schema-derived usage examples to the tool description at decoration time, without executing the tool.

```python linenums="1" hl_lines="3"
from autogen.beta import tool

@tool(add_examples=True)
def calculate_shipping_cost(destination: str, weight_kg: float) -> str:
    """Calculates the shipping cost for a package based
    on its destination and weight.
    """
    return "$15.00"
```

!!! note
    `add_examples=True` derives examples from the parameter schema only. It never calls your function, so it is safe for tools with side effects. Use `discover_examples()` below when you want examples grounded in the tool's real output.

## Execution-grounded examples with `discover_examples()`

Every tool built by the `@tool` decorator is a `FunctionTool`, which exposes an async `discover_examples()` method. It plays with the underlying callable, keeps the invocations that succeed, and returns a **new** `FunctionTool` whose description embeds those execution-grounded examples. The original tool is left unchanged.

```python linenums="1" hl_lines="11"
from autogen.beta import Agent, tool

@tool
def add(a: int, b: int) -> int:
    """Adds two integers and returns the sum."""
    return a + b

# Play with the tool to discover verified examples, then wire the
# enhanced tool into an agent.
enhanced_add = await add.discover_examples()
agent = Agent(name="MathBot", tools=[enhanced_add])
```

`discover_examples()` accepts optional bounds on the search:

```python linenums="1"
enhanced_add = await add.discover_examples(
    max_iterations=3,  # beam-search iterations
    expand_num=4,      # candidate invocations explored per iteration
    top_k=3,           # verified examples to keep
)
```

!!! warning
    `discover_examples()` **executes your tool** with generated arguments. Only call it on tools whose execution is safe and side-effect-free during discovery (or point it at a sandboxed/dry-run implementation). If the underlying callable is unavailable, the method returns the tool unchanged.

## Lower-level `play_with_tool()`

For direct access to the discovered examples — for example, to inspect them or format the description yourself — call `play_with_tool()`. It returns a `PlayResult` containing the verified `PlayExample` objects, the enhanced description, and the number of attempts made.

```python linenums="1"
from autogen.beta.tools import play_with_tool

def add(a: int, b: int) -> int:
    """Adds two integers and returns the sum."""
    return a + b

result = await play_with_tool(
    add,
    name="add",
    description="Adds two integers and returns the sum.",
    parameters={
        "type": "object",
        "properties": {"a": {"type": "integer"}, "b": {"type": "integer"}},
        "required": ["a", "b"],
    },
)

for example in result.examples:
    print(example.arguments, "->", example.result)

print(result.enhanced_description)
```

`play_with_tool`, `PlayExample`, and `PlayResult` are all exported from `autogen.beta.tools`:

```python linenums="1"
from autogen.beta.tools import PlayExample, PlayResult, play_with_tool
```

| Symbol | Description |
|--------|-------------|
| `play_with_tool(func, *, name, description, parameters, ...)` | Runs the propose/execute/observe/reflect/refine loop and returns a `PlayResult`. |
| `PlayExample` | A single verified invocation: `arguments` (the call) and `result` (the observed output). |
| `PlayResult` | Outcome of playing: `examples`, `enhanced_description`, and `attempts`. |

## Plugging in an LLM proposer

By default the candidate invocations are generated by a parameter-free, schema-guided proposer, so discovery runs with **no LLM and no cost**. To recover the paper's learned proposal step, pass an async `proposer` callable that returns candidate argument dicts for the tool's schema:

```python linenums="1"
async def llm_proposer(parameters):
    # Wrap an autogen.beta.config LLMClient to propose invocations
    # from the tool's JSON-Schema parameters.
    ...
    return [{"a": 2, "b": 3}, {"a": 10, "b": -4}]

enhanced_add = await add.discover_examples(proposer=llm_proposer)
```

See [Agent Tools](/docs/beta/tools/tools) for the full tool-authoring reference and [Model Configuration](/docs/beta/model_configuration) for wiring up an LLM client.
